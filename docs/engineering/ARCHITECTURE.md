# 架构概览

本项目是一个“多终端 + 多任务 + AI 审核/托管 + 工作流/计划任务”的运维/研发辅助平台。前端负责编排与可视化，后端负责终端托管、自动化执行、审批与审计，以及数据持久化。

## 1) 组件与边界

- **前端（Vue 3 + Pinia + Naive UI）**
  - 页面：任务/看板、终端、服务器、工作流、计划任务、AI 智能、消息中心、系统设置
  - 终端：`xterm.js` 渲染与交互
  - 移动端：表格 → 卡片化展示，底部导航 + 抽屉菜单

- **后端（Go + Fiber + GORM + SQLite / PostgreSQL）**
  - REST API：任务/终端/服务器/工作流/计划任务/系统设置
  - WebSocket：终端输出流与状态推送
  - 数据：SQLite（默认 `./data/aca.db`）或 PostgreSQL（`DATABASE_TYPE=postgres`）

- **终端托管（PTY + 可选 tmux）**
  - 统一维护会话、输入输出日志、终端状态
  - 通过“按键绑定（Key Bindings）”统一 `Enter(CR)` / `Newline(LF)` / `Esc` / `Ctrl+C` 等语义

## 2) 核心对象（概念层）

- **Server（服务器）**：SSH 目标（主机/端口/用户/分组），用于远程执行与 SSH 终端
- **ProjectGroup / Project（项目集/项目）**：分类与默认上下文（本地/远程路径、Git 仓库等）
- **Task（任务）**：执行单元（标题/状态/优先级/关联项目/关联服务器/工作目录/CLI 类型/AI 托管配置）
- **Terminal（终端会话）**：执行载体（PTY 会话、输出流、输入历史、与任务/服务器关联）
- **Workflow（工作流）**：Runbook 编排（节点/连线/上下文项目），可运行并产生记录
- **Schedule（计划任务）**：定时/单次触发器，触发任务或工作流并记录运行结果
- **Approval / Message（审批与消息）**：审批请求、审批记录、告警/通知消息（用于审计与复盘）
- **Prompt Templates（提示词模板）**：按模块拆分的可编辑模板 + 变量渲染（避免代码硬编码）

## 3) 关键流程（端到端）

### 3.1 任务执行（Task → Terminal）
1. 用户创建任务（可选绑定项目/服务器/工作目录）
2. 启动任务后创建/绑定终端会话
3. 后端写入终端输入，WebSocket 推送输出到前端
4. 任务状态随终端状态与监控规则更新（运行/暂停/完成/失败等）

### 3.2 AI 审核 / 托管（输出监控 → 审批 → 自动输入）
1. 后端监控终端输出（提示词/规则/AI 辅助）识别“需要确认/选择/密码/危险操作”等场景
2. 生成审批请求（消息中心 + 审批中心）
3. 执行输入时统一走“按键绑定”：
   - `enter` = `\r`（确认/选择）
   - `newline` = `\n`（文本换行）
   - 以及 `esc` / `ctrl_c` / `1` / `2` / `y` / `n` 等宏

### 3.3 工作流（Workflow → 节点 → 执行）
- 工作流作为 Runbook 载体，节点应显式绑定“上下文”（项目/服务器/运行目录/CLI 类型/凭证策略等），避免“Git 操作到底在哪台机器执行”的歧义。
- 推荐的节点模型见：`docs/ops/ops-workflow-design.md`

### 3.4 计划任务（Schedule → 触发 → 运行记录）
- 计划任务用于“定时巡检/定时运行 Runbook/定时执行命令”
- 每次触发都应产生日志与运行记录，方便审计与回溯

## 4) 配置层级（避免冲突）

建议遵循“全局默认 → 继承/覆盖”的层级：
- 系统设置：AI Provider / 系统规则 / 按键绑定 / 模块提示词模板
- 任务/终端/工作流：按需覆盖系统默认（并在 UI 明确展示“当前生效来源”）

## 5) 关键扩展点（面向智能运维）

- **组合节点**：将“服务器 + Git + 命令/脚本/AI”组合为一个节点，形成可复用的 Runbook Primitive
- **多服务器协同**：同一工作流节点支持 fan-out（多台机器并行）与汇聚（AI 统一判断下一步）
- **项目视角运维**：项目页聚合该项目的任务/终端/工作流/计划任务/日志/告警
