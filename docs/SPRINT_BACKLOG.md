# AI Coding Assistant - Sprint Backlog（更新：2026-01-09）

本文是基于当前代码实现与线上反馈（移动端可用性、resetData、终端输入稳定性、CLI 启动提示）重新整理的 backlog。  
目标是把 ACA 从“功能齐全”推进到“可靠、可验证、可商业化”的状态。

---

## 0) 当前状态摘要

### 已落地（本次补强）
- ✅ `reset-data`：关闭全部终端会话后，清理除 `users` 与内置 `workflow_templates` 外的全部业务数据（任务/终端/日志/审批/消息/服务器/项目/工作流/规则/AI Provider 等），避免“假重置”。
- ✅ 终端稳定性：xterm 在容器可见时再 open/fit，初次渲染补一帧 fit；WebSocket 断线自动重连，降低“命令无法输入/光标错位”概率。
- ✅ 移动端体验：Kanban/工作流/日志/AI 决策日志等长列表切换为 card 模式；移动端判定增加 coarse pointer + 横屏覆盖。
- ✅ 稳定性清理：修复组件卸载后仍持续重连 WebSocket 的问题，减少异常更新与资源泄漏。

### 仍需验证/补齐的高优先级风险
- P0：CLI 启动方式仍依赖环境（`claude` / `npx claude` / PATH），需要更强的“可配置 + 可确认 + 可恢复”的产品闭环。
- P0：移动端“终端本体”天然受输入法/屏幕限制，需明确最佳实践（全屏、快捷键、外接键盘等）和降级策略。
- P0：多代理“完整集成测试”与故障模式仍需系统化验证（Codex/Gemini/其他）。

## Sprint 11（P0）：可靠性 + 手机端闭环（建议 1~2 周）

### 目标
把“用户已反馈的问题”做到可复现、可解释、可恢复，并形成最小商业验证闭环的数据能力。

| ID | 任务 | 类型 | 验收标准 |
|---|---|---|---|
| S11-1 | CLI 启动命令可配置（任务级/CLI Profile 级） | Feature | 任务可设置 CLI 启动命令（默认/覆盖），启动失败时明确提示并可一键重试；不再依赖硬编码 `claude/codex/gemini` |
| S11-2 | Claude 启动策略增强（`claude` ⇄ `npx claude`） | Feature | 当检测 `claude` 不可用时：提示用户确认后再尝试 `npx claude`（避免误触发网络下载）；可在设置中配置默认策略 |
| S11-3 | “信息不精确就先确认”提示词框架固化 | Doc/UX | 在任务创建/自动化配置处提供模板：环境/目标/约束/进入方式（`claude`/`npx claude`）/不确定点需要提问；用户可一键应用 |
| S11-4 | 终端断线/重连 UX 统一 | UX | 断线时提示“不可输入/正在重连”；重连成功后提示并自动恢复 focus/fit；不会无限刷屏 |
| S11-5 | 移动端终端最佳实践与降级说明 | Doc | 文档与 UI 帮助入口：推荐全屏模式、快捷键按钮、外接键盘；说明手机端不可避免的限制 |
| S11-6 | resetData 回归测试与范围说明 | Test/Doc | 后端测试覆盖 resetData；前端 Settings 文案与行为一致（清理后各列表可刷新到空状态） |

## Sprint 12（P1）：审批治理深化（建议 1~2 周）

### 目标
把“自动审批”从功能升级为“可控治理”：降低误放风险，提高可解释性与可回溯性。

| ID | 任务 | 类型 | 验收标准 |
|---|---|---|---|
| S12-1 | 审批风险分级与强制人工确认 | Feature | 对高危模式（如 `rm -rf`、`git push`、写入敏感路径等）强制 manual；smart/auto_yes 不可绕过 |
| S12-2 | 审批记录可读性优化（去噪/聚合） | UX | 审批内容去 ANSI、截断策略可配置；同类提示合并展示；支持关键字检索 |
| S12-3 | 规则集模板与导入导出闭环 | Feature | 系统/任务/终端规则可一键套用模板；导入导出后可立即生效并可回滚 |
